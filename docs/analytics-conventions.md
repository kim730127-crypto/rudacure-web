# 홈페이지 트래픽 계측 기준

대상: www.rudacure.com (production). 계측 도구는 Vercel Web Analytics 하나다.
근거 문서: 「홈페이지 접속 분석 보고서」 RC-WEB-2026-001 (2026-08-17 - 09-16).

---

## 1. 봇 제외 기준

### 1.1 왜 필요한가

2026년 8-9월 집계에서 방문자 1,273명 중 자동 수집으로 판정되는 몫이 절반에 가까웠다.
방문자 수를 그대로 인용하면 실제 독자의 세 배 가까운 숫자를 말하게 된다.
아래 기준을 적용한 값만 사외에 제시한다.

### 1.2 판정 규칙

세 규칙을 순서대로 적용한다. 하나라도 걸리면 제외한다.

| 번호 | 규칙 | 근거 |
|---|---|---|
| B1 | 운영체제가 `GNU/Linux`인 방문자 | 데스크톱 방문자의 15.6%가 리눅스인 구성은 기업 방문자에게서 나오지 않는다. 2026-09-10 11시(KST) 한 시간에 몰린 54대가 전부 이 조합이었고 뉴스 기사를 번호순으로 훑었다 |
| B2 | 브라우저가 `curl`, `Chromium`(헤드리스), `UC Browser` | 사람의 브라우저 선택으로 설명되지 않는다 |
| B3 | 국가별 방문자당 페이지뷰가 1.25 미만인 국가의 방문자 | 화면 하나를 열고 이탈하는 집단. 2026-08/09 기준 29개국 378명 |

**B3의 경계값 1.25는 관측에서 나왔다.** 같은 기간 한국 5.30, 일본 2.79, 인도 1.74, 미국 1.65가
연속 분포이고, 그 아래는 싱가포르 1.00, 영국 1.00, 중국 1.08, 아일랜드 1.17로 1.0 근처에 뭉친다.
1.25는 이 두 무리 사이의 빈 구간이다. 다음 집계에서 분포가 달라지면 경계값을 다시 잡고,
그 사실을 보고서에 적는다.

### 1.3 대외 인용은 핵심 독자 수를 쓴다

B1-B3은 「확실히 봇인 것」을 걷어내는 음성 판정이라 경계선에 걸친 집단이 남는다.
2026-08/09 기준으로 잔여가 733-905명인데, 이 안에는 열람 깊이 1.65로 B3을 통과한 미국 357명이
통째로 들어 있고, 그 안에 2026-09-10 한 시간에 몰린 크롤러 54대가 섞여 있다.

**그래서 반대 방향으로 센다. 방문자당 2.0화면 이상을 연 국가만 합산한 값을 핵심 독자로 두고,
보고서와 사외 자료에는 이 숫자 하나만 쓴다.** 2026-08/09 기준 458명이다.

경계값 2.0은 분포에서 나왔다. 한국 5.28과 일본 2.71 위에는 소규모 국가뿐이고, 바로 아래는
인도 1.74와 미국 1.65로 뚝 떨어진다. 그 빈 구간이 2.0이다.

B1-B3의 잔여값은 **대조용으로만** 남긴다. 두 수치가 크게 벌어지면 그 자체가 분포가 바뀌었다는 신호다.

### 1.4 규칙이 아닌 것

- **아일랜드·싱가포르 같은 특정 국가를 이름으로 제외하지 않는다.** B3이 걸러내면 걸러지는 것이고,
  실제 방문이 늘면 자동으로 남는다. 국가명 하드코딩은 그 반대 상황을 볼 수 없게 만든다.
- **IP 대역 대조는 포함하지 않는다.** Vercel Web Analytics는 IP를 보관하지 않는다.
  따라서 B1-B3은 모두 정황 판정이며, 이 점을 수치 옆에 적는다.

### 1.5 표기 방법

수치에는 기준을 함께 적는다.

> 핵심 독자 458명 (열람 깊이 2.0 이상 국가 합산, 2026-08-17 - 09-16)

기준이 바뀐 첫 회차 보고서에는 **적용 전후 값을 나란히 싣는다.** 그래야 추세가 끊긴 이유가 보인다.

### 1.6 산출 방법

`scripts/analytics-report.mjs`가 Vercel Web Analytics API에서 원자료를 받아 B1-B3과 핵심 독자를
함께 낸다.

```
VERCEL_TOKEN=xxxx node scripts/analytics-report.mjs --from 2026-08-17 --to 2026-09-16
node scripts/analytics-report.mjs --input tmp/raw-2026-09.json   # 토큰 없이 재계산
```

토큰이 없거나 막혔다면 `--help`가 브라우저 콘솔로 원자료를 받는 절차를 출력한다.

## 2. Custom event 정의

이벤트 이름과 속성은 `src/lib/analytics-events.ts`에 고정돼 있다. 새 이벤트를 만들기 전에
그 파일을 먼저 본다. 대시보드가 비슷한 이름으로 채워지면 어느 쪽도 못 쓰게 된다.

| 이벤트 | 발화 지점 | 속성 | 읽는 방법 |
|---|---|---|---|
| `pipeline_cta_click` | 파이프라인 페이지 하단 CTA | `target` (ir/contact), `locale` | 파이프라인을 읽은 뒤 실제로 IR로 넘어간 비율 |
| `ir_contact_click` | IR 페이지 하단 두 경로 | `channel` (email/form), `locale` | IR 열람이 접촉으로 이어진 비율 |
| `document_download` | 특허 증명서, 논문 PDF | `kind`, `id`, `locale` | 어떤 자산이 실제로 내려받아지는가 |
| `contact_form_start` | 문의 폼 첫 입력 | `locale` | `contact_submit`과 짝지어 폼 이탈률 |
| `contact_submit` | 문의 폼 전송 성공 | `type`, `locale` | 문의 유형 분포 |
| `not_found` | 404 페이지 진입 | `path`(정규화), `locale` | 살아 있는 깨진 링크 목록 |

### 2.1 속성 작성 규칙

- **저카디널리티만.** Vercel은 속성값을 정확히 일치하는 값끼리 묶는다. 원본 URL이나 자유 입력
  텍스트를 넣으면 행이 한없이 늘어나 표가 못 쓰게 된다. `not_found`의 `path`는 로케일 구간을
  떼고 숫자 구간을 `:n`으로 바꾼 뒤 보낸다.
- **개인정보 금지.** 이름, 이메일, 회사명, 메시지 본문은 어떤 속성에도 넣지 않는다.
  `contact_submit`이 싣는 것은 문의 *유형*이지 보낸 사람이 아니다.
- **UI 문구를 이벤트 이름으로 쓰지 않는다.** 버튼 라벨은 바뀌고 이벤트 이름은 바뀌면 안 된다.

### 2.2 로컬에서 이벤트가 안 보이는 이유

`next start`로 띄운 로컬 서버에는 `/_vercel/insights/script.js`가 없다. 스크립트가 없으면
`@vercel/analytics`는 development 모드로 판정해 `track()`을 조용히 버린다. 로컬에서 확인하려면
브라우저 콘솔에서 `window.vam = "production"`을 설정한 뒤 동작시키고 `window.vaq`를 본다.

## 3. UTM 부착 규칙

### 3.1 왜 필요한가

2026년 8-9월 기간 중 UTM 파라미터가 한 건도 쓰이지 않았다. 같은 기간 BIO 컨벤션, BioJapan
비즈매치, Luma 행사 페이지에서 유입이 있었지만 어느 행사가 얼마를 만들었는지는 말할 수 없다.
그리고 전체 페이지뷰의 82.8%가 referrer 없이 들어온다. 메일과 QR로 들어오는 트래픽은 referrer를
남기지 않으므로, UTM을 붙이지 않으면 추적 수단이 아예 없다.

### 3.2 파라미터 규칙

모든 값은 **소문자, 하이픈 구분**이다. 대소문자가 다르면 Vercel은 다른 값으로 센다.

| 파라미터 | 필수 | 값 | 설명 |
|---|---|---|---|
| `utm_source` | 필수 | `bio`, `biojapan`, `luma`, `kddf`, `saramin`, `email`, `qr`, `linkedin` | 트래픽이 출발한 곳 |
| `utm_medium` | 필수 | `partnering`, `booth`, `qr`, `email`, `social`, `listing` | 접촉 수단 |
| `utm_campaign` | 필수 | `<행사약칭>-<YYYYMM>` 예: `bio-202606`, `biojapan-202610` | 회차 단위 |
| `utm_content` | 선택 | `namecard`, `deck-p12`, `booth-panel`, `followup-1` | 같은 캠페인 안에서 어느 매체인지 |

### 3.3 예시

```
https://www.rudacure.com/en/pipeline?utm_source=biojapan&utm_medium=partnering&utm_campaign=biojapan-202610
https://www.rudacure.com/ja/ir?utm_source=qr&utm_medium=qr&utm_campaign=biojapan-202610&utm_content=namecard
https://www.rudacure.com/ko/ir?utm_source=email&utm_medium=email&utm_campaign=ir-202610&utm_content=followup-1
```

### 3.4 착륙 지점 선택

- 파트너링 미팅 상대에게는 **해당 언어의 `/pipeline`**. 회사 소개부터 시작하지 않는다.
- 투자자에게는 **해당 언어의 `/ir`**.
- 일본 상대에게는 `/ja/...`를 준다. 일문 페이지는 IR을 포함해 전부 번역돼 있는데도
  2026-08/09 기간 일문 IR 방문자가 1명이었다. 링크를 영문으로 주면 일문 페이지는 계속 안 열린다.

### 3.5 만드는 방법

`tools/utm-builder.html`을 브라우저에서 열어 항목을 고르면 링크와 QR용 단축 형태가 나온다.
손으로 조립하지 않는다. 오타 하나가 캠페인 행 하나를 통째로 갈라놓는다.

### 3.6 읽는 방법

Vercel Analytics의 Referrers 패널 옆 **UTM Parameters** 탭에서 확인한다.
행사 종료 후 2주까지를 한 회차로 보고, 같은 `utm_campaign` 값으로 묶어 방문자 수와
`pipeline_cta_click` / `ir_contact_click` 발생 수를 함께 적는다. 방문자 수만으로는
행사 성과를 말할 수 없다.
